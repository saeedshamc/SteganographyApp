# فاز ۲ — پلن کامل Open Stego (آموزشی · متن‌باز · شفاف)

سند نقشهٔ راه. **هنوز پیاده‌سازی نشده.** هدف پروژه: ابزار حریم‌خصوصی و **آموزش عمومی** steganography؛ همه بتوانند ببینند و بفهمند سیستم چطور کار می‌کند.

---

## فلسفهٔ محصول

Open Stego یک پروژهٔ **متن‌باز آموزشی** است:

| اصل | معنا در عمل |
|-----|-------------|
| شفافیت | الگوریتم، فرمت، و جریان hide/extract در docs و Lab دیده می‌شود |
| قابل‌بازبینی | کد Rust در دسترس؛ هیچ «جادوی مخفی» برای اجرا در بینندهٔ سیستم نیست |
| دموی زنده | کاربر می‌تواند با چشم ببیند: cover → دادهٔ پنهان → استخراج → (اختیاری) اجرای payload |
| استفادهٔ درست | حریم‌خصوصی، کلاس، پژوهش، تست امنیت دفاعی — نه فریب کاربر نهایی |

سوال رایج: «چرا با دبل‌کلیک روی PDF در Acrobat برنامهٔ داخلش بالا نمی‌آید؟»  
جواب آموزشی (که باید در Lab/docs باشد): چون بیننده‌های استاندارد فقط فرمت خودشان را تفسیر می‌کنند؛ دادهٔ stego را برنامه نمی‌دانند. **استخراج فقط با ابزار آگاه (Open Stego) و معمولاً پسورد انجام می‌شود.** این رفتار طبیعی فرمت‌هاست و برای دموی شفاف هم مناسب است: همه می‌بینند که «پنهان‌سازی ≠ اجرای خودکار در سیستم‌عامل».

## ۱. دموی «فایل اجرایی داخل cover» — نسخهٔ درست و شفاف

### ۱.۱ هدف آموزشی (همان چیزی که می‌خواهی نشان بدهی)

می‌خواهی همه ببینند:

1. یک برنامه (مثلاً یک ابزار کوچک متن‌باز یا فیکسچر دمو) را می‌توانی داخل عکس یا PDF **مخفی** کنی.  
2. فایل cover همچنان مثل عکس/PDF عادی باز می‌شود.  
3. با Open Stego (و پسورد) همان برنامه **استخراج** می‌شود و در صورت تمایل **اجرا** می‌شود.  
4. کل مسیر روی صفحه قابل‌دیدن و قابل‌توضیح است — مناسب کلاس، README، ویدیوی دمو، و review متن‌باز.

### ۱.۲ جریان پیشنهادی محصول (Demo / Reveal)

```text
[Hide]
  انتخاب cover (PNG/PDF/…) + انتخاب payload (متن / فایل / برنامه)
  → رمزنگاری + پنهان‌سازی
  → خروجی: cover هنوز بازشدنی است

[در بینندهٔ عادی سیستم]
  دبل‌کلیک روی cover → فقط همان عکس/PDF باز می‌شود
  (این خودش یک نکتهٔ آموزشی است)

[در Open Stego — حالت Demo / Reveal]
  باز کردن همان cover داخل اپ
  → نمایش cover (پیش‌نمایش تصویر یا لینک «باز کردن با برنامهٔ پیش‌فرض»)
  → وارد کردن پسورد → Extract با مراحل دیده‌شده روی UI
  → اگر payload برنامه باشد: Save یا Run با تأیید واضح
```

این همان حس «هم cover دیده می‌شود هم برنامه درمی‌آید» را می‌دهد؛ فرقش این است که **اجرا از مسیر شفاف Open Stego** است تا همه بفهمند چه اتفاقی می‌افتد — نه اجرای پنهان پشت Acrobat/Photos.

### ۱.۳ اجزای فنی این دمو

1. **`payload_kind`**: `Text` | `File` | `Executable`  
2. **فیکسچر دمو** در ریپو: یک برنامهٔ بی‌خطر کوچک (مثلاً hello-world یا اسکریپت تست) برای ویدیو/کلاس — نه باینری مشکوک  
3. **صفحهٔ Demo در GUI**: ویزارد چندمرحله‌ای با توضیح هر قدم (Hide → Cover هنوز سالم است → Extract → Run)  
4. **CLI آموزشی**:  
   `stego demo run` یا مستند یک اسکریپت در `docs/LEARNING.md` که همان مسیر را چاپ می‌کند  
5. **متن UI شفاف**: «این برنامه از داخل cover استخراج شد؛ فقط چون خودت تأیید کردی اجرا می‌شود.»

### ۱.۴ آنچه عمداً طراحی نمی‌کنیم (برای شفافیت متن‌باز)

ویژگی‌هایی که کاربر را فریب می‌دهند یا مسیر را از ابزار آموزشی جدا می‌کنند، در محصول نیستند — مثلاً اجرای بی‌سروصدا فقط با باز کردن cover در بینندهٔ سیستم‌عامل، بدون Open Stego.  
دلیل: با هدف «همه ببینند چطور کار می‌کند» در تضاد است؛ دموی خوب **مراحل را نشان می‌دهد**، پنهان نمی‌کند.

## ۲. چشم‌انداز کامل فاز ۲

### ۲.۱ هستهٔ فنی

| آیتم | فایدهٔ آموزشی / کاربردی |
|------|-------------------------|
| پروفایل `Fast` / `Balanced` / `Paranoid` | نشان دادن trade-off سرعت Argon2 و مقاومت |

| `FORMAT_VERSION` v2 + مهاجرت مستند | تکامل شفاف فرمت |
| `payload_kind` شامل Executable | دموی کامل‌تر برای کلاس |

## ۴. معماری Executable در دمو

```text
PayloadMeta {
  kind: Text | File | Executable { os_hint?: Windows | Linux | Any }
  filename, extension, size, sha256
  ...
}
```

**GUI بعد از Extract:**

1. Decrypt + verify checksum  
2. نمایش kind، نام، اندازه، hash کوتاه  
3. پیش‌فرض: **Save**  
4. **Run**: یک تأیید واضح («این فایل را خودت از cover استخراج کردی؛ اجرا کنی؟»)  
5. اختیاری: دکمهٔ «باز کردن cover با برنامهٔ پیش‌فرض سیستم» کنار پیش‌نمایش داخل اپ  

**CLI:**

```text
stego extract --input cover.pdf -o demo-tool.exe
stego extract --input cover.pdf -o demo-tool.exe --run --i-understand
```

## ۵. خارج از scope محصول (برای حفظ هویت آموزشی)

این‌ها عمداً ساخته نمی‌شوند چون با «شفافیت برای همه» جور درنمی‌آیند:

- اجرای بی‌سروصدا فقط با دبل‌کلیک در بینندهٔ سیستم، بدون Open Stego  
- ابزار فریب انجمن فایل / LNK / ماکرو به‌عنوان ویژگی  
- cracker پسورد فایل دیگران  
- ادعای «غیرقابل‌کشف مطلق»  

هر چیزی که مسیر را از «ابزار قابل‌مشاهده» به «رفتار پنهان سیستم‌عامل» ببرد، در پلن نیست.
